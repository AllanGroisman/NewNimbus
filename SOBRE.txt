==============================================================
NIMBUS — Sobre a aplicação
==============================================================

O Nimbus é uma plataforma SaaS de automação de marketing por
WhatsApp focada em ofertas. Ele faz scraping de produtos em
promoção (hoje no Mercado Livre, com suporte planejado a
Amazon, Shopee e Americanas), permite organizar essas ofertas
em campanhas por categoria e dispara as mensagens em grupos
de WhatsApp do próprio usuário, em horários e cadência
configuráveis.

A ideia é tirar o trabalho manual de quem hoje monta grupos
de "promoção/achadinhos" e copia-cola ofertas o dia inteiro:
o Nimbus encontra, formata e envia.


--------------------------------------------------------------
1. PRINCIPAIS FUNCIONALIDADES
--------------------------------------------------------------

[ Conta e autenticação ]
- Cadastro de usuário com nome, email, senha e telefone
- Login com email + senha (senha guardada com hash bcrypt)
- Sessão persistida via JWT (token salvo no navegador)
- Auto-login enquanto o token for válido (TTL de 30 dias)
- Atualização de perfil (nome, telefone) e troca de senha
- Logout em qualquer dispositivo

[ Persistência por usuário ]
- Cada conta tem seu próprio estado salvo no servidor:
  campanhas, números conectados, grupos de WhatsApp
  vinculados, modelos de mensagem, agendamentos
- Os dados sobrevivem a reinícios do servidor e entre
  navegadores/dispositivos do mesmo usuário
- O frontend salva automaticamente (debounced) sempre que
  algo muda — não há botão "Salvar tudo"

[ Conexão com WhatsApp ]
- Cada usuário pode adicionar múltiplos números de WhatsApp
- A conexão é feita escaneando um QR Code (Baileys)
- As credenciais ficam salvas em disco no servidor, então
  o número fica logado entre reinícios
- Listagem de grupos em que o número participa
- Criação de novos grupos pelo Nimbus
- Geração e revogação de link de convite
- Saída de grupos

[ Campanhas (grupos de envio) ]
- Cada campanha tem:
  - Nome
  - Categorias monitoradas (Gamer, Bebê, etc.)
  - Modelo de mensagem com variáveis ({produto}, {preco},
    {preco_antigo}, {desconto}, {loja}, {link})
  - Janela horária de envio (ex: 09–12h e 14–18h)
  - Intervalo entre mensagens
  - Cooldown para não repetir o mesmo produto
  - Filtros: faixa de preço (mín/máx num slider único de 2
    thumbs), desconto mínimo, avaliação mínima, vendas
    mínimas e palavras-chave
  - Lista de grupos de WhatsApp vinculados

[ Scraping de ofertas ]
- Busca de ofertas no Mercado Livre via Puppeteer
- Cache de 5 minutos por categoria para reduzir tráfego
- Filtros aplicáveis na consulta (desconto mínimo, preço
  máximo, limite)
- Categorias suportadas hoje: Gamer (MLB1144), Bebê (MLB1384),
  Eletrônicos (MLB1051), Casa (MLB1574) e Beleza (MLB1246)
- Estrutura preparada para adicionar novas categorias e fontes

[ Envio de mensagens ]
- Envio individual de texto ou texto + imagem
- Broadcast: mesma mensagem para vários grupos em sequência,
  com intervalo configurável (default 4s) para reduzir risco
  de bloqueio do WhatsApp
- Quando o produto é do Mercado Livre, o link cru é trocado
  por link curto de afiliado (com a TAG do usuário) antes do
  envio — gera comissão sem ação manual

[ Programa de afiliados Mercado Livre ]
- O usuário cadastra TAG + cookie de sessão do painel de
  afiliados em Configurações → "Afiliados ML"
- Cookie é salvo em disco no servidor (data/affiliate.json,
  que está no .gitignore — não vai pro git)
- Botão "Testar conexão" aceita uma URL de produto colada
  pelo usuário e gera um link curto de teste; resultado vem
  como link clicável (a home do ML não funciona — só páginas
  de produto/oferta geram link curto)
- Status de saúde: distingue cookie expirado (HTTP 401/403)
  de URL não-afiliável (200 sem short_url) — só o primeiro
  marca o cookie como "ruim"
- Cache de 7 dias por link cru → short_url, pra não bater
  no endpoint do ML toda hora
- Pausa automática: enquanto não houver TAG + cookie
  configurados, todas as campanhas que dependem do ML ficam
  pausadas (não fazem scrape nem envio). Banner amarelo no
  Dashboard e na página da campanha avisa, com atalho pra
  Configurações. O botão "Enviar próximo agora" também fica
  bloqueado nesse estado

[ Configurações ]
- Conta: editar perfil e trocar senha
- Segurança: alterar senha, dispositivos conectados, 2FA
  (placeholder visual)
- Notificações: email, push, relatório semanal, produtos
  pendentes de revisão
- Fontes e categorias: lojas e categorias ativas
- Modelo padrão de mensagem aplicado a campanhas novas
- Afiliados ML: TAG, cookie e teste de conexão
- Aparência: tema claro / escuro / automático
- Zona de perigo: excluir conta

[ Painel ]
- Dashboard com visão geral das campanhas
- Lista de produtos vindos do scraping
- Página WhatsApp com gerenciamento de números e grupos
- Página Assinatura (placeholder do plano)
- Sidebar com atalhos e indicador de status por campanha
  (verde = conectado, vermelho = desconectado, laranja =
  pausado por afiliado, cinza = sem grupos)
- Aba "Fila" da campanha mostra cada item agendado com
  TODOS os campos sempre visíveis (Produto, Loja, Categoria,
  Preço, Preço antigo, Desconto, Adicionado, Imagem, Link).
  Campos ausentes aparecem como "—" pra dar visibilidade do
  que veio do scraping
- Layout responsivo para uso no celular


--------------------------------------------------------------
2. FLUXO TÍPICO DE USO
--------------------------------------------------------------

1. O usuário cria uma conta (nome, email, senha)
2. Configura TAG + cookie de afiliados ML em Configurações
   (sem isso, as campanhas de ML ficam pausadas)
3. Conecta um número de WhatsApp escaneando o QR
4. Cria uma campanha (ex: "Achados Gamer")
5. Vincula um ou mais grupos do WhatsApp à campanha
6. Define filtros (ex: -30%, até R$ 2.000) e janela horária
7. O Nimbus passa a buscar ofertas que batem nos critérios
8. Conforme o agendamento, dispara as mensagens nos grupos
   (links do ML viram link curto de afiliado automaticamente)
9. O usuário acompanha o histórico e ajusta filtros/template


--------------------------------------------------------------
3. DECISÕES DE PRODUTO (NOTAS)
--------------------------------------------------------------

- O scraping roda no PC do usuário/servidor onde o backend
  está hospedado — exige máquina ligada
- A persistência é em arquivos JSON (sem banco) — simples,
  suficiente para o estágio atual e fácil de migrar depois
  para PostgreSQL/Mongo quando o produto crescer
- O JWT é assinado com um segredo que é gerado uma vez e
  guardado em backend/data/.jwt_secret — pode ser
  sobrescrito definindo a env JWT_SECRET
- Os credenciais do WhatsApp (Baileys) NÃO ficam no
  arquivo de estado do usuário; ficam em backend/auth_states
  e estão no .gitignore
- A configuração de afiliados ML (TAG + cookie) é global do
  servidor, não por usuário — o cookie expira de tempos em
  tempos e precisa ser refrescado manualmente. Variáveis de
  ambiente ML_AFFILIATE_TAG e ML_AFFILIATE_COOKIE têm
  precedência sobre o arquivo, pra facilitar deploy
- Decisão de pausar campanhas sem afiliado configurado:
  preferimos não enviar a enviar links sem comissão. Quando
  o cookie expira, o sistema cai pro link cru (melhor enviar
  sem comissão do que perder a oferta) — mas se NUNCA houve
  configuração, a campanha fica parada esperando setup
